# グループモード詳細仕様

## モード概要

グループモードは、公民館などの地域施設で開催される俳句ワークショップに特化した設計です。ファシリテーター主導のもと、多数の参加者が共通の季語で作句し、相互鑑賞と学習を行います。

## 設計思想

### コアコンセプト
- **スケーラビリティ**: 10-50人規模のワークショップ対応
- **ファシリテーター主導**: 明確な進行管理機能
- **集合知の活用**: 参加者全体での学び合い
- **データドリブン**: 統計分析による振り返り

### 想定利用シーン
1. 公民館での定期俳句教室（月1回など）
2. 文化イベントでの体験ワークショップ
3. 高齢者向け生涯学習プログラム
4. 地域コミュニティの句会活動

## ユーザーロール

### 1. ファシリテーター
ワークショップの進行管理者

**権限**:
- セッション作成・削除
- 参加者管理
- 季語設定
- フェーズ進行制御
- メッセージブロードキャスト
- レポート出力

**UI画面**: ダッシュボード形式の管理画面

### 2. 参加者
ワークショップで作句する一般参加者

**権限**:
- セッション参加
- 俳句作成・編集
- AI支援利用
- 投票参加
- 集合写真閲覧
- 個人統計閲覧

**UI画面**: シンプルな作句・投票画面

## ユーザーフロー

### 標準的なワークショップの流れ

```
【準備フェーズ】
1. ファシリテーターがセッション作成
2. 季語と時間設定
3. QRコード/アクセスコード配布
   ↓

【参加フェーズ】
4. 参加者がコード入力して参加
5. 待機画面で他の参加者を待つ
   ↓

【作句フェーズ】（15分）
6. 季語の説明表示
7. 各自で作句
   - AI提案機能利用（任意）
   - 推敲支援利用（任意）
8. 完成して提出
   ↓

【投票フェーズ】（10分）
9. 全作品（匿名）を閲覧
10. 良いと思う句に投票（3票）
    ↓

【結果発表フェーズ】
11. ランキング発表
12. AI講評
13. 集合写真公開
14. 個人統計閲覧
    ↓

【終了フェーズ】
15. レポートダウンロード
16. 次回予告（任意）
17. セッション終了
```

### 所要時間
- 準備: 5分
- 参加受付: 5分
- 作句: 15分
- 投票: 10分
- 結果・講評: 10分
- **合計**: 約45分

## 技術実装詳細

### 状態管理

```typescript
interface GroupModeState {
  session: {
    id: string;
    name: string;
    facilitator: string;
    accessCode: string;
    kigo: {
      season: string;
      word: string;
      description: string;
    };
  };
  phase: 'waiting' | 'composing' | 'voting' | 'results' | 'ended';
  participants: Array<{
    id: string;
    name: string;
    haiku: string | null;
    hasVoted: boolean;
    badges: string[];
  }>;
  haikus: Array<{
    id: string;
    authorId: string;
    text: string;
    votes: number;
  }>;
  collectivePhoto: string | null;
  aiCommentary: string | null;
  statistics: {
    totalVotes: number;
    averageVotes: number;
    participation: number;
  };
}
```

### データフロー

```
[Facilitator Dashboard] ─── フェーズ制御 ───→ [State]
                                                  ↓
[Participant Interface] ←── 状態同期 ───────── [State]
         ↓
   [Claude API] ←── AI機能 (提案/推敲/講評)
         ↓
   [Response] ───────────────────────────────→ [UI Update]
```

## スケーラビリティ考慮

### パフォーマンス最適化

**大規模参加者対応**:
- 仮想スクロール（投票画面）
- ページネーション（50作品以上の場合）
- 非同期データ読み込み

**API呼び出し最適化**:
- バッチ処理（複数俳句の一括分析）
- キャッシング（季語辞書データ）
- レート制限対策（リクエスト管理）

## アクセシビリティ

### 公民館環境への配慮

1. **大画面対応**: プロジェクター投影を想定
2. **音声ガイド**: 画面読み上げサポート（オプション）
3. **紙資料との併用**: 印刷可能なレポート

### 多様な参加者への対応

- 視覚障害: ハイコントラストモード
- 聴覚障害: 視覚的フィードバック重視
- 運動障害: キーボード操作完全サポート
