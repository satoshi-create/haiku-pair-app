## Phase 2: 基盤強化と機能拡張（6ヶ月）

### 目標
本格運用に向けた技術基盤の構築とユーザー体験の向上

### 2.1 バックエンド実装（2ヶ月）

**現状の課題**:
- クライアントサイドのみ（データ永続化なし）
- APIキーの露出リスク
- リアルタイム同期なし

**実装内容**:

```
技術スタック:
- Backend: Node.js + Express
- Database: Supabase (PostgreSQL)
- Authentication: Supabase Auth
- Real-time: Supabase Realtime / WebSocket
```

**データモデル**:
```sql
-- Users
CREATE TABLE users (
  id UUID PRIMARY KEY,
  name TEXT,
  email TEXT UNIQUE,
  role TEXT, -- 'facilitator' | 'participant'
  created_at TIMESTAMP
);

-- Sessions
CREATE TABLE sessions (
  id UUID PRIMARY KEY,
  name TEXT,
  facilitator_id UUID REFERENCES users(id),
  access_code TEXT UNIQUE,
  kigo_season TEXT,
  kigo_word TEXT,
  phase TEXT, -- 'waiting' | 'composing' | 'voting' | 'results'
  created_at TIMESTAMP,
  started_at TIMESTAMP,
  ended_at TIMESTAMP
);

-- Haikus
CREATE TABLE haikus (
  id UUID PRIMARY KEY,
  session_id UUID REFERENCES sessions(id),
  author_id UUID REFERENCES users(id),
  text TEXT,
  syllables JSONB, -- [5, 7, 5]
  submitted_at TIMESTAMP
);

-- Votes
CREATE TABLE votes (
  id UUID PRIMARY KEY,
  session_id UUID REFERENCES sessions(id),
  voter_id UUID REFERENCES users(id),
  haiku_id UUID REFERENCES haikus(id),
  voted_at TIMESTAMP
);

-- Badges
CREATE TABLE badges (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES users(id),
  badge_type TEXT,
  earned_at TIMESTAMP
);
```

**API設計**:
```
POST   /api/sessions          # セッション作成
GET    /api/sessions/:id      # セッション取得
POST   /api/sessions/:id/join # セッション参加
POST   /api/haikus            # 俳句投稿
POST   /api/votes             # 投票
GET    /api/users/:id/stats   # 個人統計

# AI Proxy（APIキー保護）
POST   /api/ai/suggest        # 俳句提案
POST   /api/ai/proofread      # 推敲支援
POST   /api/ai/haiga          # 俳画生成
POST   /api/ai/commentary     # 講評生成
```

## リスクと対策

### 技術的リスク

| リスク | 影響 | 対策 |
|--------|------|------|
| **API料金高騰** | 運用コスト増 | 使用量制限、キャッシング |
| **API障害** | サービス停止 | フォールバック機能、ローカル処理 |
| **スケーラビリティ** | パフォーマンス低下 | クラウドインフラ、CDN |

### 運用的リスク

| リスク | 影響 | 対策 |
|--------|------|------|
| **公民館の協力終了** | 実証実験不可 | 複数拠点確保 |
| **ユーザー離れ** | コミュニティ縮小 | 継続的改善、価値提供 |
| **競合サービス** | シェア減少 | 差別化（文化特化、教育重視） |

### 文化的リスク

| リスク | 影響 | 対策 |
|--------|------|------|
| **文化の商業化批判** | 評判悪化 | 非営利運営、教育重視 |
| **伝統軽視の批判** | 俳句界からの反発 | 文化尊重、専門家との協働 |
| **AI依存の懸念** | 創造性低下 | 教育的アプローチ強調 |
